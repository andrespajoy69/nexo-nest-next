MVP · Mesa de ayuda inteligente

Nexo

Centraliza las solicitudes de TI y los reportes de ciberseguridad en una sola plataforma, con triaje automático, semáforo y SLA.

Presentación del proyecto http://localhost:3002
01 · Problema

El soporte se fragmenta

  • Las solicitudes llegan por correo, chat o llamadas sin priorización.
  • Los incidentes de seguridad se mezclan con soporte operativo.
  • No hay visibilidad del tiempo de atención ni del responsable.
  • Los archivos adjuntos pueden propagar malware.
02 · Solución

Nexo unifica la atención

Un solo canal

TI y ciberseguridad en la misma mesa de ayuda.

Triaje automático

Eleva la urgencia ante palabras clave de riesgo.

Semáforo

Prioriza lo crítico y lo vencido.

SLA visible

Tiempo de respuesta y resolución controlado.

03 · Arquitectura

Stack y estructura

Frontend

HTML, CSS y JavaScript vanilla. SPA con rutas hash.

Backend

Node.js + Express. API REST segura por roles.

Base de datos

MySQL. Migración no destructiva.

Seguridad

JWT para sesiones, bcrypt para contraseñas.

Archivos

Evidencias en disco con hash SHA-256 y cuarentena.

Presentación

Página pública en /, aplicación en /app.

04 · Roles

Tres niveles de acceso

Usuario

Crea tickets, adjunta evidencias, comenta y confirma cierre.

Analista L1

Triaje, atención de la cola, estados, escalamiento y liberación.

Administrador

Usuarios, SLA, KEDB, auditoría, métricas y reasignación.

05 · Flujo del ticket

De la solicitud al cierre

  1. El usuario crea el ticket.
  2. El triaje ajusta la urgencia.
  3. Se calculan los tiempos de SLA.
  4. El caso entra en la cola priorizada.
  5. Un analista lo toma y gestiona.
  6. Se escala si es necesario.
  7. Se resuelve y el usuario confirma el cierre.
06 · Triaje automático

Detección de riesgo

  • Analiza asunto y descripción.
  • Detecta ransomware, malware, phishing, accesos no autorizados y más.
  • Ciberseguridad sube automáticamente a Alta.
  • Las palabras clave elevan a Crítica.
  • Se registran las coincidencias en el ticket.
07 · SLA

Tiempos controlados

Respuesta

Tiempo para la primera atención.

Resolución

Tiempo para resolver el caso.

Pausa

Se detiene en “En Espera” y se reanuda al volver a “En Progreso”.

Incumplimiento

Se registra al vencer o al resolver fuera de tiempo.

08 · Escalamiento

Derivación a L2/SOC

  • El analista escala con un motivo obligatorio.
  • El caso pasa a nivel L2/SOC.
  • Conserva su SLA original.
  • Notifica al solicitante y al personal especializado.
  • Queda registrado en el historial.
09 · Evidencias

Cuarentena preventiva

  • Todo archivo adjunto entra en cuarentena.
  • Solo el personal autorizado puede descargarlo.
  • Un analista o administrador puede liberarlo.
  • Se calcula y guarda el hash SHA-256.
  • Reduce el riesgo de malware.
10 · Base de conocimiento

KEDB

  • Artículos de autoayuda para problemas frecuentes.
  • Sugerencias mientras se escribe el ticket.
  • Administración puede crear, editar y desactivar artículos.
  • Los usuarios consultan guías sin crear tickets.
11 · Notificaciones

  • Marcar como leída o todas a la vez.
